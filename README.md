# 잔해의 탑 — 프로토타입

기획서: [design.md](design.md). 로드맵 1~2단계(코어 프로토타입 → MVP) 범위를 구현했다.

## 실행

```bash
npm install
npm run dev        # 브라우저에서 http://localhost:5173
npm run sim -- 100 # 헤드리스 자동 대전 시뮬레이터 (런 100회)
npm run build      # 타입체크 + 정적 빌드(dist/)
```

## 구조 (로직과 렌더링 분리)

| 경로 | 맡는 일 |
| --- | --- |
| `src/core/` | 순수 TypeScript 게임 로직. 렌더링에 의존하지 않음 |
| `src/core/game.ts` | 행동 비용 스케줄러, 피해 파이프라인, 효과 엔진, 트리거(턴당 3회 상한), AI, 층·경보·정비 방 |
| `src/core/dungeon.ts` | 층 생성(방 8~12개), 시야, 경로 |
| `src/core/stats.ts` | 유물 → 능력치 (플레이어·적 공용) |
| `src/core/rng.ts` | 시드 난수 (같은 시드 = 같은 런) |
| `src/data/` | 유물 43, 각인 22 (조건 = 공격·이동·피격·대기), 액티브 형태 5×원소 4, 기원 3, 몸체 2, 신 2, 적 12 + 보스 2 |
| `src/render/` | three.js 탑뷰. 기본 도형 로우폴리, 유물에 따라 부위 메시 교체 |
| `src/ui/` | HTML/CSS 오버레이 (행동 순서 바, 유물 슬롯, 각인, 로그, 모달) |
| `sim/` | 헤드리스 봇 + 시뮬레이터 (`npx tsx sim/trace.ts <시드>`로 한 런 추적) |

로직은 `GameEvent`만 내보내고, 렌더러와 HUD는 그 이벤트와 상태를 읽어 그리기만 한다.

## 구현된 규칙

- 각인 = 행동 조건 4종(공격·이동·피격·대기) + 효과 17종 + 대상 5종. 각인·액티브·적 유물이 하나의 효과 엔진을 공유한다.
- 유물 손상: 장갑 유물이 먼저 피해를 받고, 넘친 피해는 확률적으로 유물을 손상시킨다. 파괴는 봉헌에서만 일어나며 고정 슬롯은 봉헌할 수 없다.
- 봉헌 4종: 큰 일격, 각인 재발동, 쿨다운 초기화, 즉시 수리. 발밑 유물과 접목된 유물 모두 태울 수 있다.
- 원소 잔류와 복합 반응: 증기 폭발, 플라즈마, 초전도, 충돌.
- 부담이 넘치면 유물이 잠든다. 행동 비용은 DCSS식이고, 경보는 0~3단계(3단계부터 정예 무한 증원). 경험치는 탐험으로 얻는다.
- 신앙 2종(용광로의 신, 녹의 신): 계율과 은총 3단계.
- 정비 방 4종(상점, 수리, 재련, 각인)이 무작위로 하나 열린다. 구역 2개 × (3층 + 수문장).
