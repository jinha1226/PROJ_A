# 작업: 밸런스 3차 — 봇 개선 · 무기/부산물 조합 시뮬레이션 · 피해 배율 재조정

명세 기준: `design.md` 「전투 공식 v2」. 이전 기록: `docs/codex/combat-v2-log.md`.

## 왜 다시 하나
- 2차 결과(몬스터 피해 배율 0.2)는 구역 1 몬스터 한 방을 1~2로 만들어, 장갑 공식(피해 − 무작위 0~AC, 최소 1)이 사실상 작동하지 않았다. 승률은 "1씩 깎는 소모전"으로 맞았을 뿐이다
- 봇이 단순해서 무기·부산물 조합(이 게임의 핵심 성장)을 거의 시험하지 못했다. 무기별 지표는 봇의 줍기 규칙을 반영할 뿐이다

## 지켜야 할 조건 (조정 중 항상)
- **C1. 몬스터 한 방 ≥ 플레이어 슈트 기본 몸 AC × 1.5** (지금 몸 AC 3 → 구역 1 일반 몬스터의 배율 적용 후 한 방 ≥ 4.5). 시뮬레이션 출력에 몬스터별 "배율 적용 한 방"을 찍어 확인
- **C2. 몬스터 피해 배율은 원래 값에서 시작**: `ENEMY_DAMAGE_MULT = { normalBase: 0.6, eliteBossBase: 0.8, perZone: 0.2, perFloor: 0.04 }`. 낮추는 것은 마지막 손잡이이며 C1을 깨면 안 된다

## 1. 봇 두 종 (`sim/bot.ts`)
지금 봇은 `simple`로 그대로 남긴다(비교 기준). `smart` 봇을 새로 만든다. `npm run sim -- N --bot smart|simple`

smart 봇 규칙:
- **무기 평가**: 기대 턴당 피해 = 명중률(`Game.hitChance`) × 피해 ÷ 공격 시간(attackCost/100). 정예 배율, 부여 옵션 점수(아래), ★를 반영. 근접 1자루 + 원거리 1자루를 유지하려 하되 점수가 크게 높으면 예외
- **부산물 사용** (주웠을 때 선택지: 손1 부여 / 손2 부여(덮어쓰기 포함) / 슈트 칸 / 분해):
  - 옵션 점수표 `sim/optionScore.ts` (데이터 표. 옵션 id → 점수, ★ trait → 점수)로 무기 부여 가치를 계산. 덮어쓰기는 (새 점수 − 지금 점수)가 양수일 때만
  - ★ 재료(정예·금지)는 ★ 효과와 맞는 무기에 우선(짝 무기면 가산). 금지 부산물의 저주(폭주: 주는 피해 +100%, 받는 피해 +100%)는 체력·AC가 충분할 때만
  - 슈트 칸 가치 = 장갑·체력·회피·AC 증가 − 무게·약점 비용(지금 보이는 몬스터 원소 기준). 무기 부여 가치와 비교해 큰 쪽
  - 점수 초기값은 대략으로 두고, 3단계 조합 시뮬레이션 결과로 갱신한다
- **소모품**: 전투 전 체력 < 60%면 적에게 붙기 전에 플라스크. 주사제는 상황별(적 2명 이상 → 점화, 체력 < 50% → 경화, 원거리 무기 사용 중 → 집중, 도망·출구 이동 중 → 가속). 기름통이 적 옆에 있고 내가 2칸 이상 떨어져 있으면 쏘거나 친다
- **전술**: 적이 2명 이상 보이면 좁은 칸(이웃 바닥 ≤ 2)으로 물러나 싸운다. 경보 2단계부터 출구로(지금 simple과 같음)
- **레벨업**: 지금 든 무기들의 색 + 외피 회로(생존)를 섞는다 (규칙을 코드에 주석으로)

## 2. 무기 고정 시뮬레이션
- `npm run sim -- N --weapon <id> [--offhand <id>] [--no-pickup]`: 시작 손1 무기를 고정하고 무기 줍기를 끈다 (부산물은 smart 규칙으로 사용)
- 9종 각 100판(smart 봇). 지표: 승률, 도달 깊이, 기대 턴당 피해, 실측 명중률
- 결과 표를 `docs/codex/balance-r3-log.md`에

## 3. 무기 × 부여 조합 시뮬레이션
- 부산물 하나는 무기에 옵션 하나를 준다: 원소가 있으면 원소 옵션(`fire`·`cold`·`lightning`·`impact`), 없으면 부위 옵션(몸 `riposte` · 팔 `bleed` · 다리 `ambush` · 감각 `aim`). 정예·금지는 ★가 함께 붙는다 (`src/data/infuse.ts`)
- `npm run sim -- N --weapon <id> --infuse <optionId|none> [--star <trait>]`: 시작 무기에 그 부여를 미리 걸고 줍기·재부여를 끈다
- 무기 9종 × (none + 옵션 8종) = 81 조합, 각 30판(smart 봇). ★는 짝 무기(`src/data/weapons.ts` `SIGNATURE`)에만 각 30판
- 결과: 조합별 승률·턴당 피해 행렬을 `docs/codex/balance-r3-log.md`에 (행 무기, 열 부여). 지배적 조합(승률이 평균보다 크게 높음)과 쓸모없는 조합(none보다 낮음)을 따로 표시
- 이 결과로 `sim/optionScore.ts` 점수를 갱신 (점수 = 그 옵션의 평균 승률 상승분 기반)

## 4. 밸런스 조정
목표 (두 봇 기준으로 갈라 둔다):
| 지표 | simple 봇 | smart 봇 |
|---|---|---|
| 승률 | 10~25% | 35~55% |
| 구역 1 보스 전 사망 | ≤ 45% | ≤ 25% |
| 일반 몬스터 처치까지 공격 수 | 2~4 | 2~4 |
| 플레이어 실측 명중률 | 70~85% | 70~85% |
| 무기 고정 승률 (smart) | 9종 모두 최저 ≥ 최고의 60% | |
| 조합 행렬 (smart) | none 대비 모든 부여가 +0%p 이상, 최고 조합이 평균의 1.5배 이하 | |

조정 손잡이 (순서대로):
1. **몬스터 체력** (`src/data/enemies.ts` `hp`) — 처치 타수 2~4를 맞추는 1순위
2. 몬스터 명중·회피·AC 표
3. 플레이어 생존: 슈트 체력(`SUIT.hp`)·기본 AC·회피, 플라스크 회복량(`FLASK`)
4. 무기 피해·명중, 옵션 수치 (`src/data/options.ts`), ★ 효과
5. 몬스터 피해 배율 (C1을 지키는 범위에서만)

## 규칙
- git commit/push 하지 않는다 (.git 읽기 전용). 파일만 수정
- `src/render/`는 건드리지 않는다
- 시뮬레이션은 `node --import tsx sim/sim.ts ...` (sandbox에서 `npm run sim`이 IPC 오류를 낼 때). 시드는 `sim-<번호>` 고정, 비교는 같은 시드 집합으로
- 조합 시뮬레이션처럼 오래 걸리는 것은 판 수를 줄여도 되지만 표에 판 수를 적는다
- 최종 수치는 `design.md` 표와 코드에 일치. `design.md`에 「밸런스 3차」 절로 두 봇 목표·최종 지표·무기/조합 표 요약을 추가
- `npx tsc --noEmit` 통과
